### Added
- Initial project scaffold: npm workspaces monorepo (`backend`, `frontend`).
- `CLAUDE.md` governance/workflow rules and `docs/` structure (architecture, api, database, patterns, decisions, project-memory, troubleshooting, rsp-domain-spec).

- **Sifting / PQE / Interview pipeline** — fills in the previously-nonfunctional `UNDER_SIFTING` status and repurposes the old free-standing "Evaluate Applicants" action into the actual RSP pipeline order (Submitted → Sifting → Qualified → PQE score → Interview → panel tabulation):
  - Applications now move to `UNDER_SIFTING` automatically the instant they're submitted (`ApplicationsRepository.create()` sets it directly) - no manual "start sifting" step.
  - `PATCH /applications/:id/evaluate` (any status → `QUALIFIED`/`NOT_QUALIFIED`, with a 0-100 score) is now `PATCH /applications/:id/sift` (`UNDER_SIFTING` only → `QUALIFIED`/`NOT_QUALIFIED` + optional remarks, no score - sifting is pass/fail against the posting's qualification standards, not a scored evaluation). `EvaluationRow`'s form and button label updated to match ("Sift"/"Sift Applicant" instead of "Evaluate"/"Re-evaluate"); re-sifting after a decision is no longer offered.
  - New PQE score import: `POST /applications/import-exam-scores` (admin, multipart `.xlsx`/`.xls` + `jobPostingId`) parses an Excel file (new `exceljs` dependency) with "Name"/"Score" header columns, matches each row by normalized full name against that posting's `QUALIFIED` applicants, and records `Application.examinationScore`/`examinationScoredAt` on matches - unmatched rows come back in the response (not an error) for the admin to review and re-upload. `EvaluateApplicantsPage` gained an "Import PQE Scores" file upload control with an inline unmatched-rows list, and an "Exam Score" table column.
  - `PATCH /applications/:id/schedule-interview`'s guard changed from "status is `SUBMITTED` or `UNDER_SIFTING`" to "status is `QUALIFIED` **and** `examinationScore` is recorded" - interview scheduling now enforces sifting-then-PQE order. `EvaluationRow` shows an "Awaiting PQE score" hint on Qualified applications without a score yet, in place of the (disabled) button.
  - Schema: `Application.evaluationScore` dropped; `evaluationRemarks`/`evaluatedAt`/`evaluatedByUserId` renamed `siftingRemarks`/`siftedAt`/`siftedByUserId`; added `examinationScore`/`examinationScoredAt`. New audit actions `APPLICATION_SIFTED`/`APPLICATION_EXAM_SCORES_IMPORTED` replace `APPLICATION_EVALUATED`.

  - Email copy updated: the Qualified sifting email now invites the applicant to the PQE instead of vaguely promising "next steps"; new `examScoreEmail` notifies the applicant of their recorded PQE score (sent regardless of score, per the domain spec).
  - See `docs/decisions.md`'s 2026-08-08 "Sifting/PQE/Interview pipeline" entry for the full rationale and trade-offs (notably: name-only PQE matching, no enforced pass/fail threshold on the exam score, and the pipeline still stopping at `FOR_INTERVIEW`/tabulation since Deliberation remains future work).

- **Fix:** PQE score import (`POST /applications/import-exam-scores`) failed to match applicants who have a middle name on file, because the lookup only ever built a `firstName lastName` key while a real exam sheet naturally includes the middle name/initial (e.g. "Gibo R. Ormeneta" vs. the applicant's own `firstName`/`lastName` "Gibo"/"Ormeneta") - every row for such an applicant came back "unmatched" even though the name was, to a human, obviously the same. `normalizeName()` now also strips `.`/`,`, and a new `buildNameVariants()` indexes each Qualified applicant under every plausible spelling (with/without middle name, middle initial, suffix) instead of one fixed key.
- **Interview scheduling now captures date/venue/attire/notes, and the notification email actually contains them.** Previously "Schedule Interview" was a single button ("the panel will be in touch with further details") and no interview date was ever recorded anywhere. `PATCH /applications/:id/schedule-interview` now takes a `ScheduleInterviewDto` (`scheduledAt`, `venue`, optional `attire`/`notes`; 400 if `scheduledAt` isn't in the future), and `EvaluationRow`'s "Schedule Interview" action opens a form for these instead of firing immediately. Schema: `Application` gained `interviewScheduledAt`/`interviewVenue`/`interviewAttire`/`interviewNotes`. `forInterviewEmail` renders a When/Where/What-to-wear/Additional-instructions list instead of the old vague one-liner; the same details are shown to the applicant under their stage tracker on `MyApplicationsPage` once scheduled, and to the admin in `EvaluationRow`'s expanded panel.
- **Fix:** `SMTP_SECURE` was parsed with `z.coerce.boolean()` in `backend/src/config/env.ts`, which is just `Boolean(value)` under the hood - since any non-empty string is truthy in JS, `SMTP_SECURE=false` in `.env` was silently coerced to `true`, causing real SMTP delivery to fail with a TLS handshake error ("wrong version number") the moment real credentials were configured. Changed to `z.enum(["true", "false"]).transform(v => v === "true")`, which parses the string correctly. Real Gmail SMTP delivery (App Password) is now configured and verified working in this environment's `backend/.env` (gitignored, not committed).

- **Fix: applicants without the eligibility a job posting requires could apply anyway.** `ApplicationsService.submit()` previously only checked that a self-declared-eligible applicant had uploaded *some* proof document, never that their eligibility type actually matched what the posting needed - and an applicant with no eligibility on file wasn't blocked at all. Job postings can now specify `requiredEligibilityTypes` (checkboxes on the admin Job Management form: RA 1080 / CSC Professional / CSC Sub-Professional / Barangay Eligibility, alongside the existing free-text qualification field, which stays as applicant-facing context only); submitting an application 400s unless the applicant's own `eligibilityType` is one of them, and `JobPostingsListPage` disables/relabels the "Apply" button using the same check so the applicant learns why before clicking, not after. New `PATCH /api/applications/:id/withdraw` (applicant-only, no admin equivalent): 404s if the application isn't the caller's own (can't distinguish "not found" from "not yours"), 400s if the application is already `NOT_QUALIFIED`/`WITHDRAWN` (both terminal) - otherwise allowed from `SUBMITTED`/`UNDER_SIFTING`/`QUALIFIED`/`FOR_INTERVIEW`. Neither `ADMIN` nor `PANEL` had any self-account page before this, and the applicant's "My Profile" link only ever reached demographic-profile fields, not account credentials - one new `ChangePasswordPage` (`/account/password`, `ProtectedRoute` with no `role` restriction) and one "Change Password" link in `Layout`'s header (shown for any authenticated role) now serve all three roles instead of three separate implementations. Does not invalidate other already-issued tokens for the same user - see `docs/decisions.md`'s 2026-08-09 entry for why, and for the still-missing "forgot password" (no current password known) case.
